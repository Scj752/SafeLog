# SafeLog 项目总设计文档

## 1. 项目概述

**SafeLog** 是一个线程安全的同步/异步日志库，作为 C++ 学习与练习项目。
它体量适中、模块边界清晰，同时覆盖现代 C++ 工程实践中的核心知识点：
类型安全、RAII、智能指针、移动语义、模板、多线程同步、设计模式与单元测试。

- 项目根目录：`D:\Project\Trae\SafeLog`
- 语言标准：C++17
- 构建系统：CMake（≥ 3.16），零第三方依赖（测试框架为内置 60 行迷你框架）

## 2. 项目目标

| 目标 | 说明 |
| --- | --- |
| 实用工具 | 产出可直接嵌入其他 C++ 项目的日志库 |
| 学习载体 | 同一套接口：参考实现（完整可运行）+ 学习项目（TODO 练习框架） |
| 关卡驱动 | 4 个阶段 × 4 组单元测试关卡，学习项目按“红 → 绿”推进 |
| 工程质量 | 低耦合、高内聚、类型安全、线程安全、无已知缺陷 |

## 3. C++ 特性覆盖清单

| 阶段 | 覆盖特性 |
| --- | --- |
| 阶段 1 同步核心 | `enum class`、`std::optional`、`std::string_view`、纯虚接口、`override/final`、`std::atomic`、`std::shared_ptr` |
| 阶段 2 格式化与文件 | RAII（`std::ofstream`）、`std::filesystem` + `std::error_code`、线程安全时间转换（`localtime_s/r`）、策略模式 |
| 阶段 3 异步日志 | `std::thread`、`std::mutex`、`std::condition_variable`、有界阻塞队列（模板）、生产者-消费者、背压、跨线程异常隔离、移动语义 |
| 阶段 4 工厂与宏 | 简单工厂、Meyers 线程安全单例、注册表、配置对象、宏的 `do-while(0)` 与 `__FILE__/__LINE__` |

## 4. 模块划分与职责

```
┌─────────────────────────── 门面层 (stage 4) ───────────────────────────┐
│ log_macros.h          logger_factory.h (LoggerFactory / LoggerRegistry)│
└──────────────┬──────────────────────────────┬─────────────────────────┘
               │ 使用                          │ 创建
┌──────────────▼───────── 并发层 (stage 3) ────▼─────────────────────────┐
│ async_logger.h (AsyncLogger)        blocking_queue.h (BlockingQueue<T>) │
└──────────────┬─────────────────────────────────────────────────────────┘
               │ 继承并重写 Dispatch
┌──────────────▼──────────── 核心层 (stage 1) ───────────────────────────┐
│ logger.h (Logger)：级别过滤 → Dispatch → 格式化一次 → 分发到所有 sink     │
└───────┬───────────────────────────────┬────────────────────────────────┘
        │ 依赖接口                       │ 依赖接口
┌───────▼────────── 抽象层 ────┐ ┌──────▼───────────┐
│ sink.h (ISink)               │ │ formatter.h      │
│  ├─ ConsoleSink (stage 1)    │ │  └─ PatternFormatter (stage 2) │
│  └─ FileSink    (stage 2)    │ └──────────────────┘
└───────┬──────────────────────┘
        │ 操作
┌───────▼────── 基础设施层 ──────────┐
│ log_record.h (LogRecord)           │
│ log_level.h  (LogLevel 转换)       │
└────────────────────────────────────┘
```

### 4.1 基础设施层
- **log_level.h**：`enum class LogLevel` 与字符串双向转换（`ToString` / `LogLevelFromString` → `std::optional`）。零依赖。
- **log_record.h**：值类型 `LogRecord`（级别、消息、时间戳、线程 id、源文件、行号）。构造时自动捕获时间与线程 id，可安全跨线程传递。

### 4.2 抽象层
- **sink.h**：`ISink` 接口（`Write(record, formatted)` / `Flush`）。接收**已格式化文本**，与格式化器完全解耦。
- **formatter.h**：`IFormatter` 接口 + `PatternFormatter`（模式串占位符）。

### 4.3 核心层
- **Logger**：级别过滤（`std::atomic<LogLevel>` 无锁读）→ `Dispatch`（模板方法钩子）→ `WriteToSinks`（格式化一次，快照分发）。自身几乎无锁；线程安全下沉到各 sink。

### 4.4 并发层
- **BlockingQueue\<T\>**：有界阻塞队列。`Push` 满则阻塞（背压），`TryPush` 满则失败，`Shutdown` 优雅关闭并唤醒所有等待线程，`WaitEmpty` 支撑 Flush 语义。
- **AsyncLogger**：继承 `Logger`，仅把 `Dispatch` 重写为“入队”；工作线程弹出后经 `write_mutex_` 调用基类 `WriteToSinks`。异常被隔离在工作线程内，线程不死。

### 4.5 门面层
- **LoggerFactory**：按 `LoggerConfig` 组装 formatter/sink/同步或异步 logger，统一返回 `std::shared_ptr<Logger>`。
- **LoggerRegistry**：Meyers 单例注册表，按名登记/查找 + 全局默认 logger。
- **log_macros.h**：`SAFELOG_INFO(logger, msg)` / `SAFELOG_I(msg)` 等宏，先过滤再求值，自动捕获 `__FILE__/__LINE__`。

## 5. 模块耦合分析

| 耦合关系 | 形式 | 评价 |
| --- | --- | --- |
| Logger → ISink / IFormatter | 仅依赖抽象接口（DIP） | 低耦合：新增 sink/formatter 不改 Logger（OCP），可任意替换（Strategy） |
| AsyncLogger → Logger | 继承，只重写 `Dispatch` 钩子（Template Method） | 过滤/格式化/sink 管理全部复用，无重复代码 |
| AsyncLogger → BlockingQueue | 组合 | 队列独立可测，不感知日志语义 |
| Sink 之间 | 无相互依赖 | 各自持有内部锁，可独立替换 |
| Factory/Registry/Macros → 下层 | 单向依赖 | 门面层可被裁剪，核心库可独立使用 |
| tests → 两套实现 | 同一套用例分别链接 `safelog_ref` / `safelog_learn` | 关卡判定标准一致 |

## 6. 线程安全策略

| 对象 | 策略 |
| --- | --- |
| `LogLevel`（Logger 内） | `std::atomic` + relaxed 序，无锁读写 |
| `sinks_` 容器 | 互斥锁保护增删；使用时拷贝快照，缩短临界区 |
| `PatternFormatter` | 构造后不可变，`Format` 为 const，天然并发安全 |
| `ConsoleSink` / `FileSink` | 各自持有 `std::mutex`，Write/Flush 串行化 |
| `BlockingQueue` | 单互斥锁 + 三条件变量（not_empty / not_full / empty），带谓词 wait 防虚假唤醒 |
| `AsyncLogger` | 工作线程经 `write_mutex_` 写 sink；`Flush` = `WaitEmpty` + `write_mutex_` + `Logger::Flush`；析构 = Shutdown → join → Flush |
| 时间转换 | `localtime_s`（Windows）/ `localtime_r`（POSIX），避免 `std::localtime` 静态缓冲竞争 |
