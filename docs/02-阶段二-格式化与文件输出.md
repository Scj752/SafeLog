# 阶段二：格式化与文件输出

## 1. 阶段目标

在阶段 1 的骨架上扩展两个**可替换实现**：
- `PatternFormatter`：按模式串把 `LogRecord` 渲染为文本；
- `FileSink`：带按大小滚动的文件输出端。

本阶段验证阶段 1 抽象设计的正确性——**新增能力不需要改动 Logger**。

## 2. 涉及模块与文件

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 模式串格式化器 | `include/safelog/formatter.h` / `src/formatter.cpp` | 占位符替换渲染 |
| 文件输出端 | `include/safelog/file_sink.h` / `src/file_sink.cpp` | 追加写入 + 滚动 + 刷新 |

## 3. 接口清单

```cpp
// formatter.h
class PatternFormatter final : public IFormatter {
public:
  explicit PatternFormatter(std::string pattern = "[%d %t][%l][%T] %m");
  std::string Format(const LogRecord& record) const override;
};
// 占位符：%l 级别  %m 消息  %t 时间(HH:MM:SS)  %d 日期(YYYY-MM-DD)
//         %T 线程id  %s 源文件  %# 行号  %% 字面量 %

// file_sink.h
class FileSink final : public ISink {
public:
  explicit FileSink(const std::filesystem::path& file_path,
                    std::size_t max_bytes = 0,     // 0 = 不滚动
                    std::size_t max_files = 3);    // 历史文件保留数
  void Write(const LogRecord& record, const std::string& formatted) override;
  void Flush() override;
  const std::filesystem::path& file_path() const noexcept;
private:
  void RotateIfNeeded(std::size_t incoming_bytes);  // 调用前须持有锁
};
```

## 4. 模块耦合

```
PatternFormatter ──实现──> IFormatter <──Logger 持有（shared_ptr）
FileSink         ──实现──> ISink      <──Logger 持有（SinkPtr）
```

- 两个模块**互不感知**：格式化由 Logger 统一完成一次，FileSink 只接收最终文本 → sink 与 formatter 零耦合。
- FileSink 依赖 `std::filesystem`，用 `std::error_code` 重载做目录/重命名操作：文件系统错误不抛异常（构造/重开失败才抛 `std::runtime_error`，属于不可恢复的编程/环境错误）。

## 5. 关键设计与线程安全

- **PatternFormatter 不可变**：`pattern_` 构造后不再修改，`Format` 是 const 方法 → 多线程并发格式化无需加锁。
- **时间转换线程安全**：`std::localtime` 返回静态缓冲区指针，多线程下有数据竞争；实现用 `localtime_s`（Windows）/ `localtime_r`（POSIX）把结果写入栈上 `std::tm`。
- **FileSink 内部串行化**：`mutex_` 保护 `stream_` 与 `current_size_`；`RotateIfNeeded` 约定“调用前须持有锁”（注释标明），避免重复加锁。
- **滚动算法**：`app.log.(n-1) → app.log.n` 依次后移，最老文件被覆盖删除，当前文件改名为 `.1` 后以 `trunc` 重开。
- **RAII**：`ofstream` 随对象析构自动关闭，无需显式 close。

## 6. C++ 学习点

1. RAII 管理文件资源；为什么析构用 `= default` 即可。
2. `std::filesystem` + `std::error_code`：无异常错误处理风格及适用场景。
3. 不可变对象（immutable）作为最简单的线程安全手段。
4. 策略模式：`IFormatter` 可替换为 JSON/XML 格式而不动 Logger。
5. 私有方法的锁约定（“调用前须持有锁”）与注释表达。
