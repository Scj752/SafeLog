# 阶段三：异步日志

## 1. 阶段目标

把同步日志升级为**异步日志**：调用线程只做“级别过滤 + 入队”，IO 由专属工作线程完成。
核心挑战是并发正确性：队列的阻塞/关闭语义、不丢日志、有序落盘、优雅停止。

## 2. 涉及模块与文件

| 模块 | 文件 | 职责 |
| --- | --- | --- |
| 有界阻塞队列 | `include/safelog/blocking_queue.h`（模板，头文件实现） | 生产者-消费者通信 |
| 异步日志器 | `include/safelog/async_logger.h` / `src/async_logger.cpp` | 入队分发 + 工作线程落盘 |

## 3. 接口清单

```cpp
// blocking_queue.h
template <typename T>
class BlockingQueue {
public:
  explicit BlockingQueue(std::size_t capacity);
  bool TryPush(T value);      // 满/关闭 → false（非阻塞）
  bool Push(T value);         // 满则阻塞等待空位；关闭 → false
  bool WaitPop(T& out);       // 阻塞取元素；关闭且排空 → false
  void Shutdown();            // 关闭并唤醒所有等待线程（幂等）
  bool IsShutdown() const;
  std::size_t Size() const;
  void WaitEmpty();           // 等待队列排空（Flush 语义）
};

// async_logger.h
class AsyncLogger final : public Logger {
public:
  AsyncLogger(std::string name, LogLevel level = LogLevel::kInfo,
              std::shared_ptr<IFormatter> formatter = nullptr,
              std::size_t queue_capacity = 8192);
  ~AsyncLogger() override;    // Shutdown → join → Flush
  void Flush() override;      // WaitEmpty → write_mutex_ → Logger::Flush
protected:
  void Dispatch(const LogRecord& record) override;  // 改为入队
};
```

## 4. 模块耦合

```
AsyncLogger ──继承──> Logger（复用过滤/格式化/sink 管理，仅重写 Dispatch）
AsyncLogger ──组合──> BlockingQueue<LogRecord>
BlockingQueue ──泛型──> T（不感知日志语义，可独立测试复用）
```

- 队列与日志零耦合（模板参数化），AsyncLogger 与基类之间只隔一个 `Dispatch` 钩子 → 阶段 1 的模板方法设计在此兑现。
- 工作线程消费后调用基类 protected 方法 `WriteToSinks`：**异步化没有复制任何格式化/分发代码**。

## 5. 关键设计与线程安全

### 5.1 队列语义（本阶段的核心契约）
- **带谓词的 wait**：`cv.wait(lock, pred)` 天然防虚假唤醒，禁止写成 `if + wait`。
- **持锁通知**：`WaitPop` 在持锁状态下 `notify_one(cv_not_full_)`，避免“先检查后通知”造成的丢失唤醒。
- **优雅关闭**：`Shutdown` 置标志并 `notify_all` 三个条件变量；`WaitPop` 在关闭后**继续取完剩余元素**才返回 false —— 这是“不丢日志”的保证。
- **背压**：队列满时 `Push` 阻塞 → 高峰期调用线程被自然限速，内存不爆炸、日志不丢失（对比“满则丢弃”策略的取舍可在文档中讨论）。

### 5.2 AsyncLogger 生命周期
- 构造即启动工作线程；析构执行固定停止序列：`Shutdown() → join() → Logger::Flush()`。
  顺序不可颠倒：先 join 再 Shutdown 会死锁（工作线程在空队列上永远等待）。
- **Flush 语义**：`WaitEmpty()` 只保证队列排空，最后一个元素可能“已出队、未写完”；
  因此工作线程写 sink 时持 `write_mutex_`，`Flush` 再抢一次该锁即可等“在途写入”完成。
- **异常隔离**：工作线程循环内 `try/catch(...)` 包住 `WriteToSinks` —— 单个 sink 抛异常不能杀死工作线程，否则后续日志全部静默丢失且队列写满后全程序阻塞。

## 6. C++ 学习点

1. `std::condition_variable` 标准用法与三大坑：虚假唤醒、丢失唤醒、忘持锁。
2. 模板类头文件实现的原因（实例化发生在编译期）。
3. RAII 管理线程：joinable 线程析构即 `std::terminate`，必须显式 join/detach。
4. 移动语义在队列传递中的价值（`LogRecord` 含 `std::string`，移动避免深拷贝）。
5. 继承 + 钩子重写（Template Method）对比组合策略的选择依据。
